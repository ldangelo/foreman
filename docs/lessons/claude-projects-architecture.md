# Claude-Projects parity: where each capability lives

Index of the project-workspace capabilities: aggregate (stream prefix), events, main modules and the HTTP / MCP / CLI surfaces. Module paths are under `packages/foreman_server/lib/foreman_server/` unless noted. Operator-facing behaviour is in `docs/user-guide.md` ("Projects workflow"); the rules are in `CLAUDE.md` §20-§26. Every row was checked against `main`; stream prefixes are the clauses of `CommandRouter.aggregate_module_for/1`.

Multi-repo projects (E12, #603) are on `main` and enabled by default (`config :foreman_server, :multi_repo, runs: true`; `runs: false` is the kill switch). They have their own row in the table below; see also `docs/lessons/multi-repo-e2e-2026-10-21.md` and `docs/user-guide.md` "Repositories" (`GET /api/projects/:id/repositories`, `foreman project repo`, `foreman_project_repo_list`, `foreman_run_request_repo`, `foreman_task_fanout`).

## Where a change has to land

- A new aggregate: a module under `aggregates/`, a prefix clause in `command_router.ex` `aggregate_module_for/1`, and a catch-all `apply_event/2` clause. Typed event structs live in `events/` and are discovered by `EventCodec` by scanning that directory.
- A new operator command: `CommandGateway.@command_endpoint_types` (the one allowlist; `CommandController` reads it via `CommandGateway.command_endpoint_types/0`; behaviour pinned by `test/foreman_server/command_allowlist_parity_test.exs`), then the CLI, then `docs/cli-reference.md` and `docs/user-guide.md`.
- A new MCP tool: `mcp/tools.ex`, and `MCP.Policy.write_tools/0` when it writes; `test/foreman_server/mcp/tool_inventory_test.exs` pins the list, the write set and that each tool is documented in the user guide or CLI reference.
- A new setting: `Aggregates.Project.Settings` (the key whitelist `ProjectSettings.keys/0` reads), the CLI flag in `packages/foreman_cli/cmd/foreman/project.go`, the settings table in `docs/user-guide.md`.

## Verified and unverified against the live service

Verified live (evidence in `docs/acceptance/`, summarised in `docs/acceptance/parity-audit.md`; rows C8 and the residual-gaps table): GitHub webhook deliveries, force-pushes to a PR branch, check re-run and merge-conflict resolution on a real private repo (`github-live-run.md`); the four workspace PR buttons (Fix CI, Address comments, Resolve conflicts, Create PR) clicked on real PRs, unresolved review-thread reads, the `pr_auto_fix` policy off/on/bounded and GitHub's refusal of an operator merge (`live-github-protection-ui-autofix.md`, `pr-actions-live-view.md`, #653); operator merge under real branch protection, a required review and a required status check refusing it with GitHub's text and the same approval and head pin merging once met (`live-github-branch-protection.md`, 2026-10-26, #672); a PR-fix thread resuming its run's claude session on a real PR (`live-claude-prfix-resume.md`, 2026-10-26, #669); and Claude coordinator, thread, reviewer, in-flight approval and steering paths for short haiku sessions (`parity-gaps-live-run.md`, `live-claude-and-approvals.md`). `pi` with `minimax/MiniMax-M2.7-highspeed` remains the main live-verified provider path.

Not verified live: **Telegram and Slack delivery** (`foreman-mivo7`, deferred by the user: the adapters, the Slack URL rules and the env wiring are tested against fakes only); **multi-repo runs against real GitHub** (the multi-repo evidence uses local bare origins and a recording fake `gh`; real-GitHub multi-repo is out of scope); **pi per-call approvals** (cannot be built: pi has no per-tool permission prompts, so a pi run never raises an approval or a question). Covered by tests but not re-run live, as the audit records: the voiding of a merge approval by a later push (#650); a refusal by `required_linear_history` itself; Claude session resume for models other than haiku, for the fix thread of a `prompt`-mode or session-less run, for the Address comments and Resolve conflicts kinds, and for a docker-sandbox fix thread; the phase-wide effect of a Claude tool approval (S2); expiry of orphaned in-flight approvals and the old-CLI fallback. C13 (a run on the user's own machine) is deferred by the user and not built.

## Runbook

- Stop new work on a project: `foreman project pause <id> --reason ...`; in-flight runs continue, `resume` re-admits held tasks.
- Wedged coordinator (three consecutive failed turns mark it `unhealthy`): `foreman project chat <id> --restart`.
- Stop automatic PR watching: `FOREMAN_PR_WATCHER_ENABLED=false`; polling is already opt-in (`FOREMAN_PR_MONITOR_ENABLED=true`).
- Stop the schedule ticker: `FOREMAN_SCHEDULE_TICKER_ENABLED=false`.
- Stop outbound notifications: `config :foreman_server, :start_notifier?, false`, or per project `--notification-preference off`.
- Projections are rebuilt from the event log on boot.

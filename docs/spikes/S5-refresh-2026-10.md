What the bridge must additionally carry, not in `emit/2`: (a) the `{:worker_result, result}` hand-off (`jido_harness_worker.ex:157,177`) to the runner's `result_recipient`; (b) cancel and live steer toward the worker, with acks mapped to `RunSteerDelivered/Consumed/Undelivered`; (c) the artifacts Review needs (diff, changed files, commits, base sha, transcript) and the branch push result; (d) provider session ids (they are in `session_bound`, which is what makes a later provider resume possible).

Decoding rule (AGENTS.md 5.4): a frame is parsed once into a closed struct (`@enforce_keys`, AGENTS.md 5.1); the proxy then builds the atom-keyed payload `Tracker` expects (`tracker.ex:304-318`). Unknown `type` or key = reject the frame and close the socket; never `String.to_atom`.

## 5. Invariants the build must respect

From AGENTS.md (lines read on the commit) and the guards in code:

- **Merge gate is operator-only** (`AGENTS.md:47`): no worker frame, proxy path, or token scope may reach `merge_approve` or `run.pr.merge`. Frames are a closed set; a `merge`-shaped frame is a protocol error that closes the socket. Test: a frame fuzz that asserts no `CommandGateway` dispatch of those commands from any frame.
- **Remote Jobsite API stays fail-closed** (`AGENTS.md:49`): `:jobsite_api` runs `RequireAuthenticated` only (`router.ex:26-29`), which 401s when no token is set (`plugs/require_authenticated.ex:28-37`); `allow_remote_start` default off (`jobsite_controller.ex:259-268`). The worker socket gets its own connect-time auth and its own `allow_remote_workers` default off. Never reuse or loosen `allow_remote_start`; `BootRecovery` (`boot_recovery.ex:12-17`) keeps never resuming anything.
- **`hooks.host.*` forbidden** (`spec.ex:685-693`); **client never supplies repo paths** (`spec.ex:48`). A worker never sends a server path and the server never sends the worker an absolute path it did not allowlist; the assignment carries `repo_url`, `base_ref`, `branch`, never `cwd`.
- **Typed boundaries, closed frame structs** (`AGENTS.md:31,34`): parse once into `@enforce_keys` structs; unknown keys dropped or rejected per 5.4b (reject here, because a frame is an authentication boundary); no `String.to_atom`; no `Map.get(a, :k) || Map.get(a, "k")`.
- **Tracker owns sequence allocation** (`worker_protocol.ex:20-26`): never trust a worker `seq` as an event-store sequence (S5 sec. 6 `remote_seq` design stands).
- **Redaction**: stdout/stderr go through `WorkerLogPolicy` before `emit/2`; uploaded diffs and transcripts go through the same redaction as the Review archive (#761, `d98555b3`) before persisting.
- **Every guard needs a test shown to fail with the guard removed.** This is the repo's working practice (the skills `prove-a-check-can-fail` / `mutation-prove-guard-whole-suite`); `AGENTS.md` itself has no such line (grep for mutation/prove found none). Guards to prove: connect-time auth, project scope, revoked-token close, `allow_remote_workers` off, frame-type allowlist, no-atom-creation, artifact byte caps, workspace-root allowlist, exec-refusal for remote programs, `allow_remote_start` unchanged.

## 6. What is verifiable on one host vs UNVERIFIED

Verifiable on one host with a loopback worker (second BEAM or Go process on the same machine, dialing `ws://127.0.0.1`):
- Frame decoding, unknown-frame rejection, connect-time auth (valid / missing / wrong / revoked / out-of-scope project), flag-off behaviour.
- The proxy <-> `WorkerProtocol.emit/2` <-> `Tracker` <-> event-store path, heartbeat timeout and `:DOWN` handling (kill the worker process).
- `execution_target` routing on both doors and the refusal of `:exec` / hooks / shell substitution for remote targets.
- Worktree creation under `workspace_roots`, symlink and `..` escapes, branch push to a local bare repo, artifact caps and sha256 commit, server-side PR step against a local bare remote with a stubbed `gh` (stub = not proof of GitHub behaviour).
- Cancel and live steer frames against a fake provider script (as the Host sandbox already allows a substitute agent executable, `sandboxes/host.ex:49-55`).

UNVERIFIED without a second machine and a tunnel (do not claim these):
- Real NAT/firewall traversal, TLS termination at a tunnel, WebSocket idle timeouts and proxy behaviour; reconnect after a real network drop.
- A real provider (claude, pi, codex) running with the user's own credentials on another OS/architecture; git credential helpers and SSH agents on that machine.
- The server's `gh` seeing a branch pushed from another machine to the real GitHub origin; real PR creation and CodeRabbit/CI behaviour on it.
- Clock skew effects on lease/heartbeat; latency effect on live steer.

Not covered by this refresh: any measurement of effort (all minute figures are estimates); the pairing flow (excluded from the first slice, S5 sec. 4 still applies if added); `Jido` session-resume across a worker restart (S5: out of first slice, still true); an HTTP fallback transport; Windows workers.

# Authoritative Event Vocabulary

> TRD Reference: `docs/TRD/TRD-2026-96872fc5-go-elixir-cqrs-parity.md#trd-001`
> PRD Reference: `#req-010`
> Satisfaction: REQ-010

This document is the **authoritative list** of every domain event emitted by any aggregate.
It is the source of truth for typed struct generation (TRD-002) and the enforcement contract
for `EventCodec.decode!/2` (TRD-003).

All events below are emitted exclusively through `CommandRouter.dispatch/1` from an
aggregate's `handle_command/2` callback. No module may emit these events directly.

**Completeness check:** Run the script at `scripts/verify-event-vocabulary.sh` (generated by
TRD-002 once complete) to verify every `handle_command/2` that returns `{:ok, %{event_type: ...}}`
has a corresponding entry in this document, and vice versa.

---

## Event Name Collision Resolution

If two aggregates would emit the same event name with incompatible field sets (different
required fields or semantically different `stream_id` patterns), the events are given
distinct names. The emitting aggregate is part of the event's identity.

- **`PrMerged` collision:** `Run` emits `PrMerged` (stream `run:<run_id>`, fields carry
  `run_id/project_id/task_id/pr_url/branch_name`). `VcsOperation` would emit an identically
  named event with `operation_id` only. Resolved: `Run` emits `PrMerged`;
  `VcsOperation` emits **`VcsPrMerged`**.

- **`ExternalWorkerObserved` collision:** `ExternalTrigger` emits `ExternalWorkerObserved`
  (stream `external:<trigger_id>`, field `trigger_id`). `Recovery` would emit an identically
  named event with `run_id` only. Resolved: `ExternalTrigger` emits `ExternalWorkerObserved`;
  `Recovery` emits **`WorkerRecoveryObserved`**.

### Worker Aggregate (`ForemanServer.Aggregates.Worker`)

> Each maps to exactly one output event. The old open forwarding channel (`worker.record`
> with arbitrary `event_type` payload) has been replaced per the architecture decision in
> `docs/architecture/missing-components.md#153-175`.
